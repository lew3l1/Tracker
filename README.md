# Forma — Habit Tracker

Персональный трекер привычек и личного развития на чистом HTML, CSS и JavaScript. Проект не использует npm, сборщик, библиотеки, CDN или внешний сервер.

## Запуск

1. Открой репозиторий `lew3l1/Tracker` и скачай проект через **Code → Download ZIP**, либо клонируй его:
   ```bash
   git clone https://github.com/lew3l1/Tracker.git
   cd Tracker
   ```
2. Открой `index.html` в браузере. Для разработки в VS Code можно использовать Live Server или выполнить `python -m http.server 8000` и перейти на `http://localhost:8000`.

## Возможности

- Адаптивная светлая и тёмная темы.
- Переключение интерфейса на русский и английский язык с сохранением выбора.
- Формат дат, часов и времени напоминаний зависит от языка: русский — 24-часовой формат, английский — 12-часовой с AM/PM.
- На мобильных устройствах навигация закреплена снизу; прокрутка боковой панели включается только на десктопе.
- Dashboard на день: прогресс, серия, привычки и график за 7 дней.
- Создание, редактирование и удаление привычек.
- Категории: здоровье, развитие, фокус и осознанность.
- Отметки выполнения с навигацией по датам.
- Аналитика за 7 и 30 дней, календарь активности и статистика по категориям.
- Дневник с настроением и ежедневной рефлексией.
- Отдельная страница «Фокус»: Pomodoro-таймер на 25 минут, короткие перерывы на 5 минут и длинные на 15 минут.
- Персональные напоминания для каждой привычки с настройкой времени и системными уведомлениями браузера. Пропущенные напоминания не дублируются в течение дня.
- Экспорт резервной копии JSON вместе с настройками напоминаний. Для восстановления JSON-файла дважды щёлкни по круглой букве «F» в нижней части боковой панели и выбери файл.
- Без облачной настройки данные хранятся локально в браузере через `localStorage`.
- Google-вход и облачное сохранение через Supabase (после настройки внешних credentials; см. раздел ниже).

## Хранение и приватность

Данные привычек, отметок, дневника, напоминаний и темы хранятся в текущем браузере. Они не отправляются в GitHub или на сторонний сервер, но не синхронизируются между устройствами. Экспортируй JSON перед очисткой данных браузера или переносом на другой компьютер.

## Google-авторизация и облачное хранение

Кнопка **«Продолжить с Google»** и обработка OAuth с PKCE (проверкой authorization code) уже реализованы в приложении. Чтобы она заработала, создай свой проект Supabase и включи Google Provider. Без настройки внешних ключей вход и облачная синхронизация намеренно остаются выключенными.

### 1. Создай проект Supabase

1. Создай проект на [supabase.com/dashboard](https://supabase.com/dashboard).
2. В **Project Settings → API** скопируй Project URL и публичный **publishable/anon key**.
3. Впиши эти два значения в корневой файл `supabase-config.js`:
   ```js
   window.FORMA_CONFIG = {
     supabaseUrl: "https://YOUR_PROJECT_REF.supabase.co",
     supabaseAnonKey: "YOUR_PUBLIC_PUBLISHABLE_OR_ANON_KEY",
     aiFunctionName: "ai-assistant"
   };
   ```
   Клиентский ключ должен быть только публичным publishable/anon key. **Никогда не размещай в этом файле secret key, service_role key, пароль базы или ключ OpenAI.**

### 2. Включи Google Provider

1. В Supabase открой **Authentication → Sign In / Providers → Google** и включи Google.
2. В Google Cloud Console создай OAuth Client ID типа **Web application**.
3. В Google Cloud добавь в **Authorized JavaScript origins** origin приложения (например, `https://YOUR_GITHUB_USERNAME.github.io`) и адрес локального тестирования (например, `http://localhost:8000`).
4. В **Authorized redirect URIs** Google добавь callback URL, который Supabase показывает в настройках Google Provider. Обычно он имеет вид `https://YOUR_PROJECT_REF.supabase.co/auth/v1/callback`.
5. Скопируй Google Client ID и Client Secret в настройки Google Provider в Supabase. Секрет хранится только в Supabase, а не в GitHub. Если экран согласия Google находится в режиме **Testing**, добавь свой Gmail в список тестовых пользователей.
6. В Supabase открой **Authentication → URL Configuration**. В **Site URL** укажи адрес сайта. В список **Redirect URLs** добавь адрес приложения в production (например, `https://YOUR_GITHUB_USERNAME.github.io/Tracker/`) и для локального теста `http://localhost:8000/`. Redirect URL должен точно совпадать с используемым адресом.

Официальная инструкция: [Supabase — Sign in with Google](https://supabase.com/docs/guides/auth/social-login/auth-google).

### 3. Создай таблицу данных

Открой **SQL Editor** в Supabase и выполни содержимое файла [`supabase/migrations/20261025000000_user_data.sql`](supabase/migrations/20261025000000_user_data.sql). Таблица использует Row Level Security: каждый вошедший пользователь может читать и менять только строку со своим `auth.uid()`.

### 4. Проверь вход и синхронизацию

1. Обнови сайт после сохранения конфигурации.
2. Нажми на иконку профиля → **Продолжить с Google**.
3. После возврата Google Forma получит Supabase-сессию, загрузит данные этого пользователя или перенесёт текущие гостевые данные в новый аккаунт.
4. После входа привычки, отметки, дневник и выбранная тема автоматически синхронизируются с облачной строкой пользователя.
5. Перед первым тестом лучше экспортировать локальную резервную копию через значок загрузки в боковой панели.

Если ты ещё не настроил Google Client ID, Supabase URL/key или таблицу SQL, это не ошибка сайта — облачная авторизация пока не может заработать. Не публикуй секреты Google, Supabase service-role или OpenAI в репозитории.

### Что синхронизируется

В облаке сохраняются привычки, ежедневные галочки, записи дневника, настройки напоминаний и тема. Каждому аккаунту соответствует отдельная строка в `user_data`, защищённая RLS. Локальный режим продолжает работать без облака.


### Уведомления и напоминания

1. Открой в Forma раздел **«Фокус»**.
2. Нажми **«Разрешить»** для системных уведомлений браузера.
3. Для нужной привычки выбери время и включи переключатель рядом с ней.
4. Напоминание появится, если выбранное время уже наступило, а привычка ещё не отмечена за сегодня.

Уведомления работают при открытой странице Forma (в том числе в фоне, если браузер продолжает выполнять страницу). Если полностью закрыть браузер или сайт, обычный JavaScript-таймер не может гарантировать доставку. Для этого понадобится отдельная PWA/push-инфраструктура. Настройки напоминаний сохраняются локально, входят в JSON-резервную копию и синхронизируются с аккаунтом Supabase.

### ИИ-помощник: развёртывание Edge Function

Важный момент: публикация сайта через GitHub Pages **не развёртывает** серверные функции Supabase автоматически. Если чат показывает `Failed to fetch`, часто это означает, что функция `ai-assistant` ещё не опубликована в Supabase, её URL недоступен или предварительный CORS-запрос не проходит.

1. Установи Supabase CLI по [официальной инструкции](https://supabase.com/docs/guides/functions/quickstart), затем открой терминал в папке репозитория.
2. Авторизуй CLI и привяжи локальный проект к Supabase:
   ```bash
   supabase login
   supabase link --project-ref ptndtmueqfekwrkpqptc
   ```
3. Разверни функцию из репозитория:
   ```bash
   supabase functions deploy ai-assistant
   ```
4. Создай секрет `OPENAI_API_KEY` на стороне Supabase, заменив значение на свой ключ OpenAI:
   ```bash
   supabase secrets set OPENAI_API_KEY=YOUR_OPENAI_API_KEY --project-ref ptndtmueqfekwrkpqptc
   ```
   Не вставляй настоящий ключ в GitHub, `supabase-config.js`, HTML или клиентский JavaScript. Он должен храниться только в Secrets Supabase.
5. В Supabase Dashboard открой **Edge Functions → ai-assistant → Invocations / Logs** и проверь вызовы. Функция требует пользовательский JWT и дополнительно ограничивает частоту запросов.
6. Обнови GitHub Pages, закрой и заново открой чат Forma AI и отправь тестовый вопрос.

Функция вызывает OpenAI Responses API через сервер, так что ключ OpenAI не раскрывается браузеру. Вызовы ИИ могут тарифицироваться отдельно на стороне OpenAI; проверь свой API-биллинг и лимиты.

Если останется ошибка, открой Supabase → Edge Functions → `ai-assistant` → Logs. Сообщение `OPENAI_API_KEY` означает, что секрет не задан; `404` обычно означает, что функция не развёрнута или используется неверное имя; ошибки CORS/сети — проверь адрес проекта, CORS preflight и раздел Invocations.



## Публикация через GitHub Pages

Репозиторий сейчас приватный. Чтобы опубликовать сайт, открой **Settings → Pages** и настрой публикацию из ветки `main`, папка `/(root)`, если текущий тариф GitHub позволяет Pages для приватного репозитория. Можно сделать репозиторий публичным, но сначала проверь, что в нём нет личных данных. Если Pages недоступен, проект всё равно можно хранить и разрабатывать в этом репозитории, а сайт запускать локально.
